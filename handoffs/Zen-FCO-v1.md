## 4. Zen in one screen

Zen exists so people can build, learn, explore, share, teach, and steward meaningful digital work.
It preserves native code and pays for honesty at the boundaries.

Carry these ideas:

- Power is never gatekept—only made honest.
- Loom holds grammar, not answers.
- A weave may be whole or part while remaining its maker's authored work.
- No privilege by default is the keystone.
- The actor remains the actor; policy does not launder authorship.
- Authored intent and resolved observation are different truths.
- Identity says what should be resolved; provenance says what incarnation supplied it.
- Discovery and enforcement should spend the same owner truth.
- Composition consumes existing power; native code introduces only missing power.
- Generated code carries ceremony; authored code carries meaning.
- A presentation may expose power without inheriting that power.
- Refusal is better than a false success, fallback, normalization, or platform claim.
- “Proven” names the evidence and configuration that proved the claim.

The current product center is Workshop. It can hold a maker through edit, save, build, realize, and
inspect, but Builder is still the Editor's only source referrer. EDIT-1 is the current direction:
capture project-root truth, add Project Files, and give every source referrer one Editor-owned
open-by-path door.

## 6. Process doctrine

The phase prompt is scope authority. Prompt Contract v1 requires:

1. one authoritative stop-condition list;
2. standing rules by reference;
3. baseline in the prompt or inherited from the accepted predecessor END;
4. compact QR lane for bounded known repairs, production lane for architectural/maker capability,
   and source preflight for a large production prompt without fresh research;
5. substantial reports split into decision-layer RB and exhaustive evidence appendix.

A report landing begins review; it does not self-accept. Current source and load-bearing tests decide
what exists. Founder acceptance decides disposition. Private strategy is then rewritten at the
smallest correct current authority; chronology remains in reports/history.

## 7. If you are asked to write or review a phase

Before authorship:

- inspect live Git and working-tree ownership;
- read current routed law and the accepted predecessor;
- verify every premise against source;
- preflight a large prompt if research did not just perform that trace;
- state judgment calls face-up and keep horizons out of executor scope.

Before acceptance:

- read the decision-layer RB first;
- compare its claims with the prompt, source, load-bearing tests, identities, and tree ownership;
- open evidence only where risk or contradiction warrants it;
- verify negative space, not only the happy path;
- do not treat test volume or a bare green as the claim.

Before a factual correction commits, search equivalent meaning across current-facing copies. If a
known relevant copy is outside scope, ask before commit. If it is discovered only after push, repair
forward rather than rewriting honest history.
