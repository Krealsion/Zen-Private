## 4. The state of Zen at hand-off — for the next Vision, written so it needs no memory

**Repositories.** Zengine and Loom are public on GitHub under Krealsion. `Zen/` is the
workspace, a git repository since 2026-09-03 with no remote, holding the executor constitution,
`Zen/prompts/`, `Zen/reportbacks/`, `REPOSITORIES.md` and the two root documents
(`zen-orientation.md`, `zen-vision.md`); `Zen/private/` is nested inside as its own repository,
no remote, and holds the maker's material and `machine_facts.md`. The executor's memory store
is one node (routes only) plus an index. Loom and Zengine `main` are protected: PR-only, the
required checks are the MinGW-w64 lane, both Linux lanes and commit attribution; MSVC is
advisory. Merges keep merge commits titled with the phase name; squash and rebase are off.

**The law register (Zengine).** `agents/workshop.md` is a router (≤ 8 KB) over 29 registers
under `agents/workshop/` (≤ 16 KB each), 305 laws. Each law is one `##` entry: LAW (one line,
≤ 210 bytes), MEANS (≤ 3), DOES NOT MEAN (≤ 2), PROVEN BY (owner identifiers under the file
that declares them, and exact test-case strings), WHY (a decision record). 51 decision records
under `agents/decisions/` with alternatives labelled tried or argued. Source carries
`// WL-…` pointers above declarations, valid only where PROVEN BY names the declaration (rule
n). `tests/check_law_register.cmake` runs in every lane with STRICT on: identifiers must occur
in code (comments stripped), pointers must be PROVEN BY inverted, witnesses must be literal
case names, sizes are budgeted, `witness: none` and `UNWITNESSED —` debts must be echoed under
Do-not-assume (one UNWITNESSED entry today: WL-FILES-04 on libstdc++/Windows). The register
rules a–t are in `AGENTS.md`. Phase codes are retired: git history and the decision records
are the phase record; old tags inside test-case names are fossils.

**Other checks.** `check_doc_links` (both repositories) resolves every repo-local link and
refuses any path outside the repository in any tracked text file (eleven spellings,
self-tested). `check_commit_attribution` refuses any AI co-author trailer.

**Windows.** Windows is two standard libraries. MinGW-w64/libstdc++ is the maker's daily build
and the required lane; MSVC's STL is the toolchain released users are expected to use and the
advisory lane. A filesystem claim names the library it was measured on. Known: libstdc++ on
Windows cannot see a reparse point unfollowed (the Files pane asks the host via
`leaves_the_tree`); its `remove_all` deletes *through* a junction into the target (no product
code calls `remove_all`; the test fixture uses `remove_tree`); MinGW binutils ≤ 2.40 cannot
assemble `workshop.cpp` (the maker's CLion now points at MSYS2 binutils 2.45).

**The collaboration.** `Zen/executor-constitution.md` (12,173 bytes) governs the executor: the
eleven standing rules, attribution, the phase contract, the RB form (Identity · Counts ·
Choices · Decisions asked · Doc gaps · What ran · Pressure exposed · Memory, evidence in a
separate file), verification, one thread, memory (routes and standing corrections only), seams.
A prompt's first line is a phrase naming the phase; the prompt file's stem is the phase name and
the RB carries it. A cold run (a memoryless agent, the constitution and `AGENTS.md` only)
completed a real task in less time than a warm one, with four documentation gaps, all since
closed.

**The technical assessment that started this arc, unchanged.** The substrate (Loom) is
disciplined enough to build a creation machine on: one gate, frozen schemas with content-id
identity, `Unverified` bytes, additive-only protocols. The live layer today is a pure DAG of
C++-defined operators — stateless, effect-free, acyclic; everything that *does* anything is a
compiled weave. The missing layer is the interpreted, stateful, maker-authored one (state
schema, message→composite trigger, emit, migration as the default reload path), and it is
where the security model stops fighting liveness: the host evaluates it, so it is contained
and inspectable by construction. Three substrate decisions are cheap before release and
permanent after: the value kinds (no Map, no Optional/Union), `ZEN_FIELD` making every field
required, and shape-only hot reload. Workshop is 38k lines against 3.3k of operator; the drift
went to the tool. The gate for every future phase: does the *machine* advance — a usable weave
panel in minutes with no C++.

**Where the code stands for the split.** `workshop/screen.hpp` and `weave.hpp` are ~4.8k and
~3.7k lines of code (comment share 28% / 32%, down from 50%); `workshop.cpp` is the one TU that
includes both and compiles to a 50 MB Debug object. Every function has an owner register. A
split moves PROVEN BY paths and pointer paths; the applier pattern (sheet → script → proof,
regenerated from the START commit, strip-diff empty for comment-only moves) and STRICT ON are
the gate. The Win32 half of `leaves_the_tree` should move to a `.cpp` so `<windows.h>` leaves
the header graph; three text-reading tripwires over `workshop.cpp` each carry their own reader.
