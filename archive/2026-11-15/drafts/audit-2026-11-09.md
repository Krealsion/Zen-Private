# The audit of 2026-11-09, sorted

The audit (a Claude Docs doc, "Zen audit: Loom and Zengine", private) read Loom at `eb31a275` and
Zengine at `425c5ff0`, built both, and ran no tests. Vision checked eight of its claims in the
source and each held (2026-11-09). Every finding is below, once, with where it goes.

## 1. Already in motion

- The host weave is a hub: `WorkshopWeave` takes about 92 shapes; `weave.hpp` changed in 99 commits
  since October 1. The pane contract and the Workshop split (decided 2026-11-08).
- One small change touches many files (the double click: 22 code files, 23 tests, 14 pages). The
  same work.
- "Write Loom, not host code" against a 47,273-line host. The same work.
- Attribution: an AI agent's commit passes the check. The attribution issue
  (`Zen/issues/attribution-check-ai-identities.md`).

## 2. Decide before release: the one-way doors

- The ABI's exact-version rule (`ZEN_ABI_VERSION 11u`, exact equality) and tables with no size
  field: freeze it, or let the tables grow.
- The schema id, 64-bit FNV-1a in the wire format: the private assessment
  (`prompts/unrun/private-security-pair.md`) and the owned-shape-names research, decided together.
- The licence: when the creations exception lands (`LICENSING.md`), and whether agent-written code
  carries the copyright the AGPL relies on (human authorship still required; a lawyer's question).

## 3. Small fixes: issues for the lane (`Zen/issues/raid-batch-2026-11-09.md`)

- Loom: the bus's queue has no bound.
- Loom: nested values stay shared and mutable after the gate.
- Loom: Clang rejects `json.hpp`; the tools page's macOS line; no Clang lane.
- Loom: `loom-host` ends without a word when a native participant throws.
- Zengine: two quarry fonts with unverified terms.

## 4. Private: security (`prompts/unrun/private-security-pair.md`)

- Loom: on Windows, `session.key` takes the directory's ACL.
- Loom: schema ids can be made to collide on purpose; `same_identity`'s comment says otherwise.

## 5. Structure, after the baseline

- Workshop admits every artifact (`trust_every_artifact`; 23 of 25 weaves unbounded): the approval
  seat, then box by default what was not built here, before anything is shared between people.
- Law: 690 named laws in Zengine (462 Workshop, 203 verification, 25 maker) against Loom's 61. Keep
  law for invariants a stranger's weave could break and let tests carry the rest, or keep a lighter
  form as the agents' rails and say that is its job.
- Permanence on an alpha: `WorkshopSession` v9 to v14 at once, 55 shapes with several versions,
  about 1,200 lines keeping old sessions loading. Change shapes in place until a release with
  users; keep the census.
- The first step for a maker: Tally is 219 lines and 7 doors, among 623 shape names. A pane base
  with one action door (the contract's helpers), or Flow named as the beginner's height.
- Redraw what Loom is: about 20,100 lines of substrate beside a host, console, terminal, run
  manager, Python client and widget tree (1,658 lines). A sibling with a lighter standard.
- Six test sources over 250 KB, the largest 387 KB: split by case group when the lane is quiet.

## 6. Notes and small calls

- Loom's three Windows lanes are advisory, and Windows is where the founder builds; Zengine made
  MinGW required.
- `.clang-tidy` exists and no CI job runs it (18 warnings, none a defect). Optional.
- 11,011 lines of Python drive Workshop from another host (25,788 in the repository): fine if
  deliberate; it needs its own upkeep.
- A README line on how the code is made, for a reader who arrives from the vision's words on AI.
- The first maker other than the founder, and their height: Tally or Flow.
- Running the tests again: not needed, since CI runs every lane on every pull request.

## 7. Mistakes it names, kept as rails

- Restarting Zengine from zero: the debt is concentration in the host, not the foundation.
- Parallel dispatch before nested values are immutable and the queue is bounded.
- A "share your weaves" story while Workshop admits everything.
- More law to fix law.
- ABI stability by promise: make the table able to grow, then promise.
- Moving more into Loom because Loom is the good one.

## What holds

Loom's core does what its README says, builds clean under `-Werror`, and showed no memory-safety
defect; its threat model is stated narrowly; the reference pages match the code where checked.
Zengine consumes Loom as a stranger would; 25 of the shipped plan's 27 rows load a weave; its
verification is serious; its limitations page tells the truth.
