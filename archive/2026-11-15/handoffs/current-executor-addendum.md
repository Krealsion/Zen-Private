# Zen — Executor entry route

**Role:** bridge from an authorized task to its current owners  
**Refreshed:** 2026-09-10  
**Scope authority:** the founder's current task or phase prompt

This is a route, not a selected production packet. The former EDIT-1 card is retained in Git;
EDIT-1 has landed and its implementation checklist must not be replayed as current work.

## Begin here

1. Read the authorized task and [executor constitution](../../executor-constitution.md).
2. Read each affected repository's `AGENTS.md`, then the subject owners it routes to.
3. Use [the registry](../../REPOSITORIES.md) for repository paths and Git for live state.
   Compare with the task's baseline; preserve newer and unrelated work.
4. Read the relevant current [Workshop capability and sequence](../goals/workshop.md), not a
   historical handoff's proposed next step.
5. Open reportback evidence and source only as the task's claims require.

For Workshop pane work, the two routes are
[behavioral ownership](../../Zengine/agents/workshop.md) and
[the shared pane protocol](../../Zengine/agents/panes.md). Read both for an extracted pane.
For substrate questions, start at [Loom's router](../../Loom/docs/CONTEXT.md).

## Carry forward

Preserve the behavior supplied by the former owner as well as the new request's lifetime.
For each operation, establish its subject, the state that can change while it is pending, how
the answer is validated, and what happens when it no longer applies. Existing methods live in
[verification fixtures](../../Zengine/agents/verification/fixtures.md); pane behavior belongs to
its routed register. A passing test moved to another consumer no longer protects its old owner.

The [orientation](../../zen-orientation.md#8-working-rhythm) owns prompt temperature, review,
acceptance, and consolidation. The constitution owns execution, verification, commits, and
memory. This card does not copy those contracts or grant a continuation after a stop.
